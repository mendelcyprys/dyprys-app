        reading a result
        
Every line tells you why it matched

        
Two searches run on every question and their results are merged: a meaning
          search that understands a description, and a keyword search that finds
          your exact words. The result line says which one found the passage — and how sure it is.

        how a question finds its answer
        
Two halves, then two stages

        
The two halves keep search honest — meaning alone misses a remembered phrase, keywords
          alone miss a description. Routing keeps it fast: it reads about one book in seventy
          instead of the whole library.

      

      

        

          1
          

            
Route

            
Each book is profiled into a handful of directions. A query scores every book by its best one and keeps only the closest few — no approximate index, so nothing is lost that a full scan would have found.

            
3,453 books → 51.4% read

          

        

        

          2
          

            
Search both halves

            
Exact cosine over the routed passages for meaning, and a keyword index for literal words — the exact-phrase probe still sweeps the whole library, so a remembered sentence is never routed past.

            
vector · meaningBM25 · keywords

          

        

        

          3
          

            
Fuse by rank

            
The two rankings combine by position, not score — a cosine and a keyword score aren't comparable numbers. What surfaces is the passage both halves, in their own terms, put near the top.

            
reciprocal rank fusion

        what it guarantees
        
Built to be trusted with a library you can't re-check

      

      

        

          never shows what it can't prove
          
A quote is the real bytes, or nothing

          
Every passage is verified against a stored hash before it is shown. Edit a book and the changed passages are withheld — never displayed as stale — while the rest keep their vectors, matched by content, not position.

        

        

          verified under real crashes
          
Interrupted, never corrupted

          
Embedding is resumable to a single passage: a vector is written before the count that claims it. Killed mid-run with SIGKILL at 73 of 195 passages, then resumed — every vector came back bit-identical to a clean rebuild.

        

        

          drafts you can check
          
An answer, with its receipts

          
Ask it to write a summary and every quotation is checked character-by-character against the source and cut if it fails. Locations come from the index, never the model — and when the library has no answer, it says so and retries once itself.

        

        

          for a person or an agent
          
Speaks JSON as fluently as prose

          
Every command — search, status, health, history — takes --json, so an assistant can drive the whole tool structurally. A short operating manual travels with it, telling the agent which search to run when.

        

      

    

  


  

    

      
One idea carries the design: a passage is the unit of everything. It has an id, that id is its row in the vector file, and ids are dense per book — so a book, a chapter or a shelf is a contiguous slice of one array, reached with a single memory-mapped read.

      

        
# point it at a folder of text, once
$ dyp add ~/library
$ dyp embed --model model.gguf   # the one slow step, resumable
$ dyp route

# then ask, for the rest of the library's life
$ dyp ask "why can a nerve impulse only travel one way"
